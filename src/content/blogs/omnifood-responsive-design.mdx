Omnifood is an HTML and CSS project in my GitHub portfolio. It is a useful context for exploring what makes a website feel coherent across devices without requiring a complex application framework.

## Establish a visual system

A consistent website uses a small collection of spacing values, type sizes, colors and reusable layout patterns. This gives headings, cards and buttons a shared visual language. Rather than applying unrelated styles to each section, design decisions can be represented through CSS custom properties and reusable classes.

## Build responsive sections

A grid can organize cards on wider screens, while a narrower viewport may need a single column. Flexbox works well for aligned navigation and controls. Fluid sizing and sensible maximum widths help avoid oversized text and awkwardly long lines. Breakpoints are most useful when they respond to the content rather than targeting only a specific device model.

## Accessibility and performance

A polished design should remain usable with a keyboard, meaningful heading structure and readable contrast. Images should have appropriate alternative text, and decorative motion should respect reduced-motion preferences. Optimizing images and reserving their layout space can help a page remain stable during loading. These are general frontend practices I want to apply, not an accessibility audit of the Omnifood repository.

## Why the basics matter

Frameworks can improve developer productivity, but they do not replace understanding the browser. Layout, responsive behavior and semantic markup remain important in React and Next.js applications. Omnifood belongs to the part of my journey focused on those foundations.
